# 贴贴收纳夹（Pixel Stash）
## 游戏产品与开发需求文档

**项目类型：** H5 轻度休闲益智游戏  
**核心玩法：** Grid-based Sticker Packing Puzzle（网格贴纸空间装填）  
**目标规模：** 50 个精心设计的关卡

---

# 1. 产品概述

## 1.1 游戏概念

玩家获得一组可爱的像素风贴纸，需要将它们合理地放置在有限大小的收纳纸页中。

不同贴纸具有不同的网格形状。玩家需要通过移动、旋转和调整位置，找到合理的空间布局。

核心规则：

- 所有贴纸都必须放入收纳纸页。
- 贴纸不能超出纸页边界。
- 普通贴纸之间不能重叠。
- 不同贴纸之间必须至少保留一个白色空格（上下左右方向）。
- 允许最终纸页存在空白区域，不要求填满所有格子。
- 一关可以有多种正确解法，任何符合规则的布局都可以通关。

部分关卡会引入特殊机制，例如旋转能力、镂空贴纸、特殊贴纸叠放等。

## 1.2 核心体验

希望玩家获得三种体验：

1. **空间规划：** 思考不同形状的贴纸如何合理组合。
2. **发现惊喜：** 发现贴纸之间隐藏的组合关系，例如饼干可以放在盘子上。
3. **完成满足感：** 所有贴纸都放好后，得到一张完整、可爱的像素贴纸收藏页（可以保存图片，作为手机壁纸等）。

游戏不以速度、反应或竞争为核心，而以空间观察、尝试和调整为核心。

## 1.3 视觉方向

采用统一的可爱像素风（Kawaii Pixel Art）。

参考方向：
- 像素尺寸规整，色彩柔和。
- 贴纸具有独立、清晰的剪裁轮廓。
- 每张贴纸外围有白色描边，模拟真实的 Die-cut Sticker。
- 背景采用淡色纯色纸张、手帐网格等视觉元素。
- 整体简洁、干净，突出贴纸本身。

美术不追求复杂动画或精细场景，重点是素材风格统一、形状辨识度高。

# 2. 核心游戏规则

## 2.1 收纳纸页（Board）

每一关有一张矩形网格纸页。

Board 包含：
- 宽度和高度。
- 可放置区域。
- 不可放置区域（Blocked Cells）。
- 可选的预设贴纸位置（后续扩展）。
矩形不一定为正方形，长宽比不限制。

## 2.2 贴纸（Pieces）

每张贴纸由若干个相连的网格单元构成。

例如：

```text
■ ■
■
```

代表一张占据三个格子的 L 型贴纸。

每张贴纸具有：
- 唯一 ID。
- 美术素材。
- 网格占位形状（Shape Mask）。
- 当前摆放位置。
- 当前旋转角度。
- 是否拥有旋转能力。

需要区分三层数据：
- 形状库：用 `shapeId` 标识可复用的 Shape Mask。
- 主题贴纸库：用 `stickerId` 标识一种贴纸，记录主题、美术素材和 `shapeId`。不同贴纸可以共用一种形状，但物件轮廓必须与占位形状相符。
- 关卡贴纸实例：本关实际需要摆放的每一张贴纸。每个实例有本关内唯一的 `id`，通过 `stickerId` 引用主题贴纸，并分别记录位置、初始方向、当前旋转角度和旋转能力。

每关按需选用所属主题库中的贴纸，不要求该主题的所有贴纸都在每一关出现。同一种贴纸可以在同一关重复出现多次，例如 3 张完全相同的咖啡贴纸；它们共用同一份美术和形状，但分别移动、判定和完成放置。旋转名额按实例计算，给其中一张解锁旋转，不会同时解锁另外两张。

**重要：美术图片和逻辑占位形状必须分离。**

程序根据 Shape Mask 判断能否放置，不根据 PNG 图片的透明像素进行碰撞检测。

## 2.3 基础摆放规则

### A. 不允许越界

贴纸的所有占位格子都必须处于 Board 范围内。

### B. 不允许重叠

不同贴纸不能占据相同的格子。

### C. 贴纸之间需要留白

不同贴纸的占位格子之间，至少需要保留一个空白格。

暂定规则：
- 上下左右方向不能直接相邻。
- 斜角接触允许。
- 同一张贴纸内部的格子可以相邻。

即不同贴纸之间的占位格子，曼哈顿距离必须至少为 2。

### D. 允许剩余空白

不要求所有可用格子都被贴纸覆盖。所有贴纸都成功放置，即可通关。
因此，一关可以有多种正确摆法。

### E. 障碍格

部分关卡会出现不可放置区域。
障碍格：
- 不可放入贴纸。
- 不可被贴纸覆盖。
- 不需要玩家进行额外操作。

# 3. 特殊玩法机制

## 3.1 旋转能力（Rotation Ability）

旋转不是所有贴纸默认拥有的能力，而是每关可以分配的特殊能力。该机制增加空间规划之外的能力分配决策。

规则：
- 每关配置可解锁旋转的贴纸数量。一关中最多允许 3 张贴纸获得旋转能力，具体每关提供多少旋转名额，由关卡配置决定。
- 玩家可以自行选择哪些贴纸获得旋转能力。任意一张贴纸都可以被赋予旋转能力。
- 获得能力后，可以以 90° 为单位旋转，支持四个方向。
- 未获得能力的贴纸保持初始方向。
- 旋转不能导致贴纸越界、重叠或违反留白规则。

## 3.2 特殊叠贴（Sticker Stacking）

某些贴纸之间存在隐藏的叠放关系。作为游戏彩蛋和特色机制。

例如：
- 小圆饼干（Cookie）
- 小圆盘子（Plate）

正常情况下，两张贴纸需要分开放置。

当玩家尝试将饼干拖到盘子上时，游戏发现两者是兼容组合，允许它们叠放。

设计要求：
- 只有预先指定的兼容贴纸可以叠放，普通贴纸依然遵守不能重叠的规则。
- 叠放成功后展示上下层关系。采用预设的相对位置和吸附锚点，而不是允许任意重叠。
- 玩家通过尝试自行发现，不必在首次出现时直接告诉玩家。
- 叠放组合应有明确的视觉反馈。

第一版只实现少量指定组合，例如饼干 + 盘子。

## 3.3 镂空贴纸（Hollow Stickers）

作为后续关卡机制。
部分贴纸的内部存在空洞（即镂空部分），这些空洞不属于该贴纸的占位格子，其他贴纸可以放入镂空区域。这些贴纸例如：
- 花环。
- 甜甜圈。
- 相框。
- 蝴蝶结边框。

内部空间仍然需要满足贴纸之间的留白规则。

## 3.4 暂不加入的机制

第一版暂不加入：
- 生命值或失败惩罚。
- 任意角度旋转。
- 普通贴纸自由重叠。
- 复杂物理效果。
- 贴纸固定方向等额外限制。

# 4. 玩家交互

## 4.1 基础操作

| 操作 | 效果 |
|---|---|
| 拖动贴纸 | 移动贴纸 |
| 点击旋转按钮 | 旋转 90° |
| 点击已放置贴纸 | 重新选中 |
| 拖动已放置贴纸 | 调整位置 |
| 点击重置 | 重置当前关卡 |
| 点击提示 | 使用提示系统 |

移动和放置时，贴纸应自动吸附到网格。

如果位置不合法（超出边框、和已有贴纸重合等）：
- 不允许完成放置。
- 给出清晰的视觉反馈。
- 玩家可以继续调整。

## 4.2 放置反馈

- 合法位置：显示正常贴纸轮廓。
- 非法位置：显示红色或其他明确的错误反馈。
- 可行提示位置：显示闪烁的半透明贴纸轮廓。
- 叠贴成功：播放吸附动画，显示上下层关系。
- 通关：展示完整的贴纸收藏页。

# 5. 提示系统（Hint System）

提示系统是重要功能，需要基于程序求解器实现，不依赖唯一标准答案。

当玩家点击提示，以下三种提示随机出现。

## Hint 1：展示一个可行摆放位置

对一张尚未放置的贴纸，寻找一个合法位置，并在 Board 上闪烁显示。

要求：
- 保留玩家当前已经放置的所有贴纸。
- 展示的摆放位置必须属于至少一种完整可行解。
- 如果需要旋转，提示同时说明需要解锁旋转能力。
- 只展示一种可行摆法，不意味着这是唯一答案。

## Hint 2：检查已放置贴纸

逐一检查玩家已经放置的贴纸，直到找到一张满足以下条件的贴纸：

该贴纸当前位置至少存在一种完整解法，可以在保留该贴纸当前位置的前提下完成剩余关卡。其他已放置贴纸允许重新移动。

反馈：显示闪烁的绿色半透明贴纸轮廓。

如果没有任何一张已放置贴纸处于可行位置，显示：
「当前贴纸的位置没有一个是合适的。」

## Hint 3：检查整体布局

将玩家目前所有已放置的贴纸全部锁定，检查剩余贴纸能否完成放置。

反馈：

- 存在完整解法：「当前布局可以继续完成哟！」
- 不存在完整解法：「当前布局已经无法完成了，调整一下吧~」

该提示用于发现看似合法、实际上堵死后续空间的布局。

# 6. 关卡设计系统

## 6.1 难度设计维度

关卡不能只依赖增加贴纸数量或缩小画布，需要综合使用以下维度。

| 维度 | 具体变化 | 难度影响 |
|---|---|---|
| 贴纸数量 | 增加贴纸数量 | 增加组合规划复杂度 |
| 形状复杂度 | L、T、Z、凹凸不规则形状 | 增加空间判断难度 |
| 形状相似度 | 多张相似但不完全相同的贴纸 | 增加辨识与规划难度 |
| 画布尺寸 | 调整宽度、高度 | 改变可用空间 |
| 富余格子数量 | 调整可用空间与贴纸总面积的差值 | 控制空间松紧 |
| 富余格子分布 | 空白空间的位置和分布 | 影响实际可摆放性 |
| 障碍格 | 增加不能放置的格子 | 限制布局 |
| 旋转名额 | 允许部分贴纸旋转 | 增加能力分配决策 |
| 镂空贴纸 | 引入可利用的内部空间 | 增加组合方式 |
| 特殊叠贴 | 允许指定贴纸重叠 | 增加隐藏组合关系 |

### 富余格子（Slack）

定义：

`Slack = Board 可用格子数 - 所有贴纸占用格子数`

Slack 作为难度参考指标，而不是唯一难度标准。

需要同时考虑：
- 空白格子的数量。
- 空白格子的可能分布。
- 贴纸之间必须保留的间隔。
- 是否存在狭窄区域。
- 是否有可利用的镂空区域。

### 解法数量（Solution Count）

每关可以存在多个正确解法。

解法数量是辅助难度指标：

| 难度参考 | 解法数量目标 |
|---|---|
| 入门 | 多种解法 |
| 简单 | 5–15 种 |
| 中等 | 2–10 种 |
| 困难 | 1–3 种 |

这些是初始设计参考值，需要结合实际试玩调整。

统计时应排除可互换贴纸实例交换身份造成的重复解，例如 3 张相同咖啡贴纸仅交换实例 ID，不应计为新解。可互换性需要同时考虑形状、初始方向、旋转和叠贴等规则，不能只看图片或形状相同；包含贴纸旋转、叠放造成的不同解。不能仅凭解法数量判断关卡难度。

## 6.2 50 关规划

建议将 50 关分为 10 个小阶段，每阶段 5 关。

| 关卡 | 主要变化 |
|---|---|
| 1–5 | 基础形状、留白规则、基本空间规划 |
| 6–10 | 引入障碍格 |
| 11–15 | 增加贴纸数量和形状复杂度 |
| 16–20 | 增加旋转能力，只允许旋转一个贴纸 |
| 21–25 | 难度升高，允许旋转最多3个贴纸 |
| 26–30 | 引入镂空贴纸 |
| 31–35 | 减少富余空间，调整空白分布 |
| 36–40 | 引入特殊叠贴关系 |
| 41–45 | 组合多种已有机制 |
| 46–50 | 综合挑战，复杂空间布局 |

每阶段应遵循：
1. 第一关介绍新机制。
2. 中间关卡逐步组合。
3. 最后一关形成阶段性挑战。
4. 难度之间有适当的起伏。不只是从容易到困难，而应该有张弛变化。例如第 15 关比较难，第 16 关可以给一关相对宽松的新机制教学。

### Board 尺寸要求

- 入门关：约 6×6 至 8×8。
- 中期关：约 7×8 至 9×9。
- 后期关：根据形状复杂度和实际求解情况调整。

以上尺寸为初始测试范围，不是强制限制。

# 7. 关卡生成与验证

## 7.1 生成方式

采用 AI 分步实现生成工具与求解器 + 程序生成候选关卡 + 用户试玩反馈。AI 负责提出设计、编写代码、生成配置和执行验证，不能仅凭文字判断关卡可解或有趣。

关卡从经过小规模验证的主题贴纸库中取件，具体建库流程见第 8.2 节。推荐使用受素材库约束的反向生成：

1. 根据本关目标难度和允许的机制，从所属主题库选择若干种贴纸，并确定每种的数量；可以只用库中的一部分，也可以重复选用同一种。
2. 为每张实际使用的贴纸创建独立实例 ID，引用已有 `stickerId`，不为每关重新创建形状或美术。
3. 使用这些实例，在本关真实的留白、障碍、初始方向、旋转名额及特殊机制限制下，搜索一个完整可行布局。
4. 保存关卡配置和至少一份参考解，再将贴纸放回待收纳区域、打乱顺序。参考解用于验证，不限制玩家采用其他正确摆法。
5. 使用求解器验证，筛选候选关卡并结合试玩调整。只要改变画布、障碍、贴纸组合、初始方向或旋转规则，就要重新验证。

不得通过任意切割完整布局来不断产生新的 Shape Mask。已有素材不足时，先调整选件、数量、画布或障碍；确实需要新形状时，按第 8.2 节回到主题库调整流程，而不是悄悄新增一张仅服务当前关卡的素材。

从真实规则下的完整布局生成，可以提供至少一份可行解；后续调整仍可能破坏可解性。如果需要增加镂空、障碍和特殊叠贴，生成器必须使用对应的真实规则进行验证，不能只检查贴纸面积。

## 7.2 求解器（Solver）

使用回溯搜索（Backtracking）或 Exact Cover 等算法。

输入：
- Board。
- Blocked Cells。
- 所有贴纸的 Shape Mask。
- 旋转权限。
- 当前已放置贴纸。
- 留白规则。
- 特殊叠贴规则。

输出：
- 是否有解。
- 至少一种完整解法。
- 可选：解法数量。
- 可选：每张贴纸的合法位置数量。

优先使用「可选位置最少的贴纸先搜索」的策略，提高求解效率。

求解器还需要支持三种提示系统所需的条件搜索。

## 7.3 关卡验证标准

每一关在给真人玩家测试前，都必须测试通过：

- 至少存在一种完整解法，所有贴纸都可以成功放置。
- 所有特殊规则均得到正确验证。
- 难度符合所在阶段的预期。
- 所有贴纸引用均有效，实例 ID 不重复；重复使用同一种贴纸时，各实例均被独立计入求解和通关判定。

# 8. 美术资产生产

## 8.1 美术生产原则

不为每关单独生成一整幅插画，采用可复用的贴纸素材库。

全游戏规划4个主题库，按第 8.2 节分批制作，按以下顺序和关卡对应：
主题1-春季-花园下午茶：关卡1-15
主题2-夏季-日式池塘花鸟：关卡16-30
主题3-秋季-美拉德色系服饰：关卡31-40
主题4-冬季-圣诞冰雪精灵世界：关卡41-50
每个主题包含：
- 20–30 种独立贴纸素材。这是主题库的素材种类预算，不是每关贴纸数量，也不是 Shape Mask 数量。
- 1 种纸页背景纹理。
- 5-6 种障碍格样式。（障碍格不是单独的灰色方块，而是场景中的装饰物，例如纸页上已经贴的一张邮票、胶带、纸页四角的装饰花纹...这些东西不能移动，玩家只能安排剩下的贴纸。）

所有主题的 UI 图标和反馈素材全部用相同的一套。

复用与数量控制：
- 每关从所属主题库选择贴纸种类及各自数量，不必用完主题库。同款贴纸可跨关复用，也可在同一关出现多张；重复实例不增加素材种类。
- Shape Mask 数量单独控制，不要求每种美术都有独有形状。通用形状可以跨主题复用，同时为主题特色物件保留少量独特形状。
- 每个主题先用少量候选形状和物件草图试做，再根据结果记录形状数量上限和贴纸素材清单；不得把 20–30 种美术素材直接等同于 20–30 种形状。
- 主题物件与形状共同设计，例如杯把可以启发侧面凸出的形状；不能先随意造形状，再硬套成不自然的物件。
- 素材库确定后，关卡默认只引用已有素材。需要新增或修改形状时，记录原因、预计使用的关卡和预算变化，并重新验证受影响的关卡。

## 8.2 AI 素材生成流程

按主题分批推进：先做春季主题的小规模验证，再扩展到该主题的完整关卡；其他主题重复这一流程。无需先完成全部 50 关，也不要一开始批量生成全部正式美术。

1. **建立候选目录。** AI 根据主题物件、对应关卡范围和第 6.2 节的机制安排，提出少量候选贴纸及 Shape Mask，记录 `stickerId`、物件名称、`shapeId` 和简单草图或占位图。物件和形状一起调整，先验证最小集合，不必立即凑满 20–30 种素材。
2. **制作可玩样本。** AI 用候选库制作少量代表关卡，覆盖该主题所需的难度和机制；只允许选用该主题当前阶段可以使用的机制。用占位图即可验证逻辑，同时挑几张贴纸制作接近最终效果的美术样本，检查手机尺寸下的轮廓、白边和留白是否清晰。
3. **验证并调整。** AI 运行求解器和实例校验，交付可玩版本，由用户试玩反馈。根据结果调整物件、形状、选件和画布；有解不等于有趣，也不等于最终画面好看。
4. **固定本批素材清单。** 样本通过后，记录该主题的形状上限、形状定义、贴纸目录和图片规格。扩展完整主题库时仍遵守预算。后续修改记录影响范围，保持关卡引用有效，不随关卡数量增长不断新增素材。
5. **分批扩展关卡和正式美术。** 在形状稳定后，两项工作可以交替或并行推进。关卡引用目录；AI 按目录生成统一风格的像素贴纸，逐张生成或从素材图中提取，去除背景并保存透明 PNG，统一像素尺寸、色板和白色描边，再与对应 Shape Mask 绑定。不需要等所有关卡布局确定后才生成正式图片，也不为重复实例重复生成图片。
6. **回到游戏验收。** AI 检查素材引用、显示尺寸、旋转对齐和逻辑占位，重新验证受影响关卡，提供可玩版本供用户确认体验；通过后再扩大制作范围。

美术图片可以超出逻辑占位格子的边缘，但必须保证视觉边界不会造成玩家对碰撞规则的误解。若图片难以匹配既定形状，优先修改图片；确需修改 Shape Mask 时，必须同步检查所有引用它的关卡。

# 9. 技术实现建议

## 9.1 核心数据结构

形状库、主题贴纸库与关卡配置分开维护。建议每关使用独立 JSON 配置，通过 ID 引用共享目录，避免各关复制并修改同一张贴纸的形状和素材。

以下 JSON 将三层数据放在一起展示关系；实际文件可以分别保存。示例中，本关只选用了春季库的两种贴纸，其中同一款咖啡出现 3 次：

```json
{
  "shapes": {
    "cup_compact": [[0,0],[1,0],[2,0],[0,1],[1,1]],
    "flower_l": [[0,0],[1,0],[0,1]]
  },
  "stickerCatalog": {
    "spring_coffee_01": {
      "themeId": "spring",
      "asset": "stickers/spring/coffee_01.png",
      "shapeId": "cup_compact"
    },
    "spring_flower_01": {
      "themeId": "spring",
      "asset": "stickers/spring/flower_01.png",
      "shapeId": "flower_l"
    }
  },
  "level": {
    "levelId": 1,
    "themeId": "spring",
    "board": {
      "width": 7,
      "height": 7,
      "blockedCells": []
    },
    "rotationTokens": 0,
    "pieces": [
      { "id": "coffee_01", "stickerId": "spring_coffee_01", "initialRotation": 0, "rotationEnabled": false },
      { "id": "coffee_02", "stickerId": "spring_coffee_01", "initialRotation": 0, "rotationEnabled": false },
      { "id": "coffee_03", "stickerId": "spring_coffee_01", "initialRotation": 0, "rotationEnabled": false },
      { "id": "flower_01", "stickerId": "spring_flower_01", "initialRotation": 0, "rotationEnabled": false }
    ],
    "stackRules": [],
    "goal": "place_all_pieces"
  }
}
```

`initialRotation` 是本关初始方向；位置、当前角度和旋转能力等运行状态按实例保存，不写回共享贴纸定义。叠贴兼容性可以由贴纸种类定义，但实际叠贴关系必须记录参与实例的 ID，不能因贴纸同款而同时移动或叠放所有副本。

正式数据结构需要进一步支持：
- 镂空形状。
- 特殊叠贴组合。
- 特殊相对位置。
- 关卡难度元数据。
- 解法统计信息。

## 9.2 逻辑模块

建议将代码拆分为：

1. Board Manager：棋盘和障碍管理。
2. Piece Manager：贴纸形状、位置、旋转管理。
3. Placement Validator：合法性判断。
4. Solver：完整解法搜索。
5. Hint Manager：三种提示逻辑。
6. Level Manager：关卡加载、重置、通关。
7. UI Manager：交互和视觉反馈。

美术素材和关卡数据尽量与游戏逻辑解耦。

## 9.3 平台要求

- H5 网页游戏。
- 优先适配手机竖屏。
- 支持触屏拖动与点击。
- 同时兼容桌面鼠标操作。
- 无需登录和服务器账号体系。
- 关卡数据可本地加载。
- 游戏进度建议本地保存。

技术栈由开发 Agent 根据实现效率选择，不需要为复杂架构增加工作量。

# 10. 开发计划

建议分为五个里程碑。整个游戏采用 AI 分步开发（vibe coding），本文描述完整目标，不要求 AI 在一次任务中实现所有功能、关卡和美术。

每次交给 AI 的任务应说明：当前阶段、需要读取的现有文件、本次修改范围、交付物和验证方式。AI 先读取现有实现及最新素材目录，再完成一个可运行、可检查的小步骤；保留用户已有修改，不因推进下一阶段而重写无关内容。

每步完成后，AI 记录已完成内容、实际验证结果、未解决问题和下一步；验证通过后再扩展依赖它的功能。关键体验节点交付可玩版本供用户反馈。逻辑原型可以使用占位图，但需尽早检查少量正式美术样本。不得仅用文字声称已实现、已可解或已完成素材生产。

下列里程碑表示主要依赖顺序。主题候选库和小规模美术验证从 M1 开始，正式素材在 M4 按主题逐批接入，M5 负责最终打磨与发布。

## M1：完善核心原型

- 先建立少量春季候选贴纸、共享形状和实例引用，支持同一关使用多张同款贴纸；用占位图和少量美术样本验证。
- 重新设计前三关，增加格子数量和贴纸数量。
- 完成基础放置、移动、旋转能力。
- 完成留白和障碍判定。
- 验证核心玩法是否足够有趣。

交付：可玩的 3 关 H5 原型。

## M2：求解器与提示系统

- 实现合法摆放搜索。
- 实现完整解法验证。
- 实现 Hint 1、Hint 2、Hint 3。
- 验证多解情况下的提示逻辑。
- 用同关 3 张相同咖啡贴纸的案例，验证独立移动、旋转名额、提示、重置和通关判定；验证可互换实例不会虚增解法数量。

交付：具有完整提示能力的核心游戏。

## M3：特殊玩法

- 实现饼干 + 盘子的叠贴彩蛋。
- 实现镂空贴纸。
- 完成对应的逻辑和视觉反馈。

交付：具备基础玩法和特色机制的游戏版本。

## M4：50 关内容制作

- 完善关卡配置系统，维护形状库、主题贴纸库和关卡实例的引用关系。
- 按主题执行第 8.2 节：候选目录、少量样本关卡、程序验证与用户试玩、固定素材清单，再分批扩展。先完成并验证春季主题，再依次推进其他主题。
- 从有限素材库批量生成候选关卡，用不同贴纸子集、同款数量、画布、障碍和该阶段允许的机制形成变化，不靠不断新增形状扩充关卡。
- 使用 Solver 验证，调整解法数量和难度，人工试玩和修改。
- 形状稳定后分批制作并接入正式美术，不把全部素材生产推迟到 50 关完成之后。
- 记录每种贴纸在哪些关卡使用及各关数量，便于检查复用与修改影响；不要求每种贴纸在每关出现，也不强制使用次数相同。

交付：50 关完整关卡数据、对应的有限主题素材库及验证记录。

## M5：视觉打磨与发布

- 补齐并打磨 M4 已分批接入的像素贴纸素材，检查全部主题的风格、轮廓与占位一致性。
- 完成 UI 和通关反馈。
- 优化手机端操作。
- 测试全部关卡。
- 输出可运行的 H5 版本。

# 11. 验收标准

最终作品需要满足：

### 核心玩法
- 玩家可以完成贴纸拖动、放置和移动。
- 非法位置能够被正确阻止。
- 留白规则正确生效。
- 允许合法的多解布局。
- 旋转名额按关卡配置执行。
- 特殊叠贴不会破坏普通碰撞规则。

### 提示系统
- 能展示当前布局下的可行位置。
- 能判断单张贴纸当前位置是否属于至少一种完整解法。
- 能判断整体布局是否仍然可完成。
- 提示结果与实际规则一致。

### 关卡
- 50 关均有至少一个完整解法。
- 难度存在明显递进和体验变化。
- 不同阶段能够体现不同的空间规划挑战。
- 没有重复堆砌相同难度的关卡。

### 体验
- 玩家无需阅读长篇规则即可上手。
- 贴纸放置反馈清晰。
- 通关反馈明确。
- 手机端拖动体验稳定。
